Kipp Calendar — Milestone 4 Implementation Plan

Adopt the Calendar-validated native-tool runtime in LinkedIn while preserving its established draft, feedback, approval, publishing, and failure contract.

Outcome: LinkedIn generation and revision become bounded, workflow-scoped native-tool sessions. The model may submit a draft candidate through one typed handoff tool; only deterministic Workflow code may notify, accept approval, read credentials, create a LinkedIn draft, or archive the idea.

1. Scope and invariants

IncludedExcluded
Native-tool generation and revision; a static LinkedIn allowlist; schema-validated draft handoff; bounded provider/tool turns; safe guard and provider failures; lifecycle metrics; parity integration coverage.Calendar behavior, LinkedIn API changes, direct model publishing, new Telegram commands or copy, backlog schema changes, generic memory, analytics dashboards, recurrence, and a universal feedback-session abstraction.
  • The only model-visible LinkedIn capability is submit_linkedin_draft. It returns an acknowledgement and cannot call GitHub, Telegram, the token vault, or LinkedIn.
  • The provider must make exactly one successful handoff call per generation or revision attempt. Prose-only output, multiple calls in a turn, unknown tools, malformed input, and exhausted budgets fail closed.
  • Publishing remains outside the model session. Only a valid, routed __approve__ interaction reaches deterministic credential lookup and createDraftPost.
  • Draft text, source idea content, feedback, provider reasoning, tokens, and provider bodies never enter lifecycle logs.
  • The existing maximum of four user feedback rounds, interaction expiry, opaque routing, status transitions, cumulative usage/cost, archive behavior, and safe Telegram failures remain unchanged.

2. LinkedIn agent contract

idea + style prompt (+ latest approved conversation / feedback)
  → runTools(provider, linkedInRegistry, LINKEDIN_ALLOWED_TOOLS)
    → ToolGuard validates submit_linkedin_draft({ draft })
    → successful handoff returns control to PipelineWorkflow
  → persist candidate + notify user
  → wait for deterministic Telegram interaction
    → feedback: start a new bounded revision tool session
    → approval: deterministic LinkedIn write + archive

Add a LinkedIn-specific module that owns its system prompt, Zod schemas, registry construction, allowlist, transcript conversion, and bounded session result. The prompt carries the existing style and quality contract: 150–300 words, engaging hook, brief personal angle, clear takeaway, engagement prompt, and professional conversational tone. On revision, it receives the canonical prior conversation plus the newest human feedback and must return a complete replacement draft.

The successful handoff output is deliberately non-authoritative: { accepted: true }. The handler records one in-memory candidate for the surrounding Workflow step. An empty or whitespace-only draft is rejected by schema; application code trims accepted text and preserves the existing step-output size guard.

3. Workflow migration

  1. Replace the fixed draft → critique → revise generation block with one native-tool session and remove the production dependency on the text-only draft, critique, and revise agents.
  2. Represent LinkedIn history as canonical tool-provider messages so generation and subsequent user revisions use the same provider abstraction. Persist only the serializable transcript needed for later feedback.
  3. Accumulate usage from every provider turn returned by the tool session. Preserve model resolution, stored cost fields, and Telegram cost lines.
  4. On a failed tool session or provider error, preserve the existing safe Workflow retry/failure behavior, emit metadata-only failure information, and do not persist a candidate, register approval controls, or mutate LinkedIn.
  5. Leave approval, token lookup, LinkedIn draft creation, archive, timeout, and Interaction Router code deterministic. No publish tool is declared or registered.
Abstraction boundary: Milestone 4 reuses runTools, provider adapters, ToolGuard, and canonical messages. It does not fold the LinkedIn and Calendar state machines together. The separate Beads item for a reusable bounded feedback-session runner remains the place to evaluate shared wait/resume mechanics.
