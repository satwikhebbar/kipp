Telegram virtual 1:1s with Google Meet

Implementation plan for Beads issue agent-harness-0sg.7. The first release books one timed, non-recurring meeting with one guest on the connected account’s primary calendar. Search saved Google Contacts by name or accept a manually entered email. Store attendees as a list so a future release can approve several addresses together. Defer Other contacts, Workspace directory search, recurring invites, guest availability, and guest replacement after sending.

Create & send invite · Change · Cancel

  1. Recognize explicit virtual meeting language and extract the guest name. Ask for missing information. Ask the owner to revise requests for multiple guests or recurring invitations before offering to book anything.
  2. Show a small set of choices when names or email addresses are ambiguous. Offer manual entry when a match is missing, a contact has no email, or Contacts access is unavailable. Even a single match appears in the final approval with its full email.
  3. Reuse Calendar scheduling and alternative slots. Choosing a slot leads to the final invite prompt with the title, date, time range and zone, recipient, and Google Meet. Any change requires fresh approval. Cancel and expiry end the draft before any Calendar write.
  4. After approval, recheck the slot. If it has become unavailable, return to scheduling and ask for fresh approval for the new slot. After booking, show the saved details and the Meet link when ready.

2. Require approval in the Calendar workflow

Extend the typed Calendar intent in src/agent/calendar.ts and workflow-owned plan in src/calendar/plan.ts. Give the planner the meeting intent and any unresolved name. Keep lookup, recipient selection, and confirmation in deterministic workflow code. Route manual email replies directly to the pending interaction. Keep resolved addresses and provider results out of model tools and transcripts. Carry explicit meeting intent across scheduling turns. A later proposal that drops the guest or conference field must still require approval.

Reuse versioned actions in src/calendar/agent-workflow.ts. Bind Create & send invite to the exact plan, guest list, workflow, owner chat, and expiry. Consume it once through the interaction router. Require valid approval at the write boundary for direct proposals and alternative slots. Route backdated or newly conflicting slots through the normal scheduling checks before trying again.

Offer alternative slots or another time for an invited request whose slot is busy. The existing Move it flow automatically creates the requested event as part of a multi-write operation, so omit that action for invited requests in the first release. Also keep invited meetings out of the personal-block move and undo path. Use their own Edit flow for changes that notify the guest.

3. Create the event and preserve the invitation on edit

  • In src/integrations/google-calendar.ts, insert the busy event with the approved guest and the connected Google account. Set the organizer’s RSVP to Yes and let the guest respond independently. Use sendUpdates=all and conferenceDataVersion=1. Request hangoutsMeet with a conference request ID stable across retries of that creation. Reuse the existing stable event ID. After an ambiguous response, read back the same event and verify Kipp’s request marker and the approved event fields.
  • Use Google Calendar’s native Propose a new time action for this timed invitation. Set guestsCanModify to false so the organizer reviews proposals and controls changes to the scheduled time.
  • Google may return a pending conference. Check the saved event with a bounded retry and show the video link when ready. If it remains pending or fails, tell the owner that Calendar saved the event and give its Calendar link when available. Recover lost Telegram confirmations from the saved event without another insert or notification.
  • Use the existing short-lived Edit action for title or time changes. Obtain fresh approval for the revised invitation. Patch the approved fields, preserve guest response state and conference data, and notify the guest for a real change. Use the event’s ETag and verify after an uncertain update to avoid overwriting a concurrent change or sending another notification. Guest changes and Meet removal are outside this edit flow.
