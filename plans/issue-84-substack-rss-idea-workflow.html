Use structured Substack content in the RSS idea workflow

When the RSS feed finds a new public Substack post, turn its complete, cleaned article into up to five distinct raw LinkedIn ideas that retain the author’s voice. Do not automatically draft or publish a LinkedIn post.

Prerequisite: Issue #83’s structured RSS-HTML extractor is complete. This plan integrates that module into the live scheduled workflow.

1. Outcome and boundaries

Extend the existing scheduled RSS handler. It will find the first feed item whose canonical URL is not already represented in Notion, parse its content:encoded HTML through the Phase 1 module, ask a bounded LLM session to select worthwhile source-grounded ideas, then save the accepted candidates as raw Notion ideas.

  • Create one to five candidates; three to five is the normal target, but fewer is correct when the article does not contain more strong ideas.
  • Keep each idea as an unstructured body: minimal needed context, one or more source passages, then its core argument. Do not add labels or properties for those pieces.
  • Set every created item to raw, use source substack, and retain the article URL using the existing storage shape.
  • Do not start PipelineWorkflow, create drafts, introduce a scraper/API fallback, process images, add an RSS persistence checkpoint, or alter production configuration.
Design boundary: this is an ordinary scheduled Worker invocation, not a durable Cloudflare Workflow with individual checkpointed steps. Its logical stages are explicit in code, while the existing per-idea Durable Object continues to provide idempotency for confirmed saves.

2. Happy-path flow

  1. The configured schedule invokes handleRssCron.
  2. Fetch and parse the configured RSS feed, then list existing Notion ideas and choose the first unseen article URL.
  3. Use the title, optional description-as-subtitle, URL, and content:encoded body to produce the clean structured article JSON from Phase 1.
  4. Start the bounded idea-agent session with that article JSON in its initial user message, explicitly marked as untrusted source material rather than instructions.
  5. The agent calls submit_substack_ideas with one to five candidate ideas. The tool accepts them after validation and returns the assembled accepted bodies.
  6. Save each accepted candidate sequentially through the existing ingest path, always with startWorkflow: false.
  7. Send one Telegram summary containing the source title, created count, and working titles; then exit.

There is intentionally no read_substack_article tool. The scheduled handler has exactly one predetermined article and has already safely projected it before the agent starts. Passing only the projected JSON is simpler and avoids a needless one-shot model round trip.

3. RSS and article preparation

Refactor the RSS item model so content:encoded and description remain distinct. The rich encoded body is the only v1 article body; description is normalized as an optional subtitle. Never substitute the description as article content.

  • Remove the existing HTML stripping and 6,000-character truncation from this path.
  • Call parseSubstackArticle before any provider session. Preserve its typed failures and make them a no-write run failure.
  • Pass no raw HTML, page URL fetching capability, image content, raw attributes, or links’ destinations to the model.
  • Retain the current feed retry behavior for transient fetch failures and the current first-unseen-item behavior.

4. Bounded idea agent

Replace the legacy free-text RSS generator with the project’s native tool-session runtime and a tool-capable provider. The initial user message contains the complete structured article and a short statement that its text is source material, not executable instructions.

The prompt tells the agent to find distinct, compelling core ideas rather than summarize the post or reproduce every section. A strong candidate has a concrete argument that can stand as a LinkedIn post, enough specificity to be credible, and enough original language to carry the author’s voice. Passages can come from one H2 section by default or from more than one section when that better expresses one coherent idea.

The agent must preserve source wording where useful, add only the short context required for standalone meaning, and end with a concise core argument. It may lightly adapt or shorten selected passages for readability, but must not invent unsupported claims, promotional teasers, or generic summaries. Distinctness applies only among candidates from this article.

Grounding approach: use the narrow structured input, prompt instruction, and tool boundary—not deterministic lexical matching. Exact source matching would reject useful light adaptation and is not required for this personal workflow.

5. Submission, validation, and saving

submit_substack_ideas is the agent’s only native tool. Its schema receives the complete candidate set:

{
  ideas: [{
    title: "Specific working headline (1–80 characters)",
    context?: "Only the framing needed for standalone meaning",
    excerpts: ["One or more selected source passages"],
    coreArgument: "The concise claim this idea makes"
  }]
}

Put every model-correctable rule in the tool input schema: one to five ideas, non-empty trimmed fields, title length, at least one non-empty excerpt, and exact normalized duplicate checks across titles, core arguments, and passage sets. Keep the tool available after an invalid submission. The native runtime will return the structured schema errors to the model transcript, allowing it to repair its candidates.

OutcomeBehaviour
Schema validation failsReturn the tool’s structured invalid-input feedback to the agent; it may submit a corrected set.
Valid submissionThe handler trims values and assembles the unlabeled Notion body in context → passages → core argument order. Return acceptance and finish the session.
Handler/internal failureTreat as a fatal operational error, not a prompt-repair problem.

Bound the session to three provider turns and three submission attempts. On acceptance, use the existing sequential ingest service and a stable per-candidate idempotency key. All items use startWorkflow: false.

6. Cadence and notifications

Update scheduled cadence selection to skip all raw ideas whose source is substack. They remain manual-only and can still be selected through the existing /generate route.

After every fully successful RSS ingestion, send Telegram a concise Markdown summary: the source-post title, number of raw ideas created, and their working titles. Do not include excerpts, page links, or a success notification for a replayed/already-known post.

7. Failure, retries, and idempotency

Failure pointResult for this runLater RSS poll
RSS fetch, missing rich body, article parse, or agent extraction failureNo ideas are written; send a concise failure alert.Retries naturally because no article URL was saved.
Invalid agent submissionReturn the schema feedback and allow repair within the bounded session.Fails cleanly if no valid submission is accepted.
Notion transient requestUse the existing Notion request retry policy.No new batch/replay state is added.
Failure after one or more accepted savesExisting per-idea idempotency protects confirmed writes; report the operational failure.Do not build a batch checkpoint/resume mechanism for this rare partial-write case.

This deliberately favors small operational complexity. Authentication repair, temporary service recovery, or manual intervention are adequate for the limited partial-write scenario; a durable batch state would add more machinery than the workflow warrants.

8. Tests and dry run

Deterministic coverage

  • Extend RSS parsing tests: preserve encoded HTML separately, retain description as optional subtitle, and reject missing rich content rather than falling back to a description excerpt.
  • Test the agent prompt boundary: only clean structured article JSON is passed, never raw HTML.
  • Test submit_substack_ideas valid assembly and every schema-repairable failure, including candidate count, required fields, title length, and within-article duplicate rules. Assert invalid feedback remains visible for a corrected resubmission.
  • Test raw-only ingest inputs, stable keys, no workflow start, cadence exclusion for Substack, Telegram success summary, and no-write extraction failures.

Qualitative pre-production dry run

Add a local dry-run command that performs RSS retrieval, parsing, and the bounded agent session but never writes to Notion, a Durable Object, or Telegram. Run it against these public posts and review the proposed raw ideas for grounding, author voice, distinctness, and usefulness as LinkedIn-draft inputs:

  • The Agentic Leader’s Field Guide
  • Dealing With Great Expectations
  • Thriving in the Age of Good Enough

Also run the standard unit, lint, typecheck, and Worker deploy dry-run checks. The long-post corpus is explicitly intended to prove there is no practical input-size issue before introducing an artificial truncation limit.

9. Implementation sequence

  1. Refactor RSS item parsing and the scheduled handler to preserve metadata/body separation and call the Phase 1 extractor for the first unseen item.
  2. Add the native tool-session prompt and submit_substack_ideas schema/handler; remove the legacy generated teaser/subIdeas path and its truncation.
  3. Route accepted candidates through existing idempotent ingestion as raw, no-workflow Substack ideas; add the success notification.
  4. Exclude Substack items from cadence while preserving manual /generate behaviour.
  5. Add deterministic tests, the local dry-run command, and run the three-post qualitative review plus quality gates.

10. Decisions retained for posterity

Article retrieval and cleanup

Use RSS content:encoded as the single v1 article source. It was verified against the configured public feed to carry complete article structure, while RSS description acts as subtitle metadata. The public page and an observed undocumented API could supply similar HTML, but each adds a second adapter without an observed RSS gap. Phase 1 cleans the body using linkedom/worker, selected over Cheerio after equivalent real/synthetic output with a materially smaller Worker import bundle.

Agent interaction

Supply the already-clean structured article directly in the initial user message. The earlier idea of a mandatory article-reading tool was removed: the agent has no choice of article, and a direct message avoids an unnecessary tool turn while preserving the same bounded content surface. Retain a single submission tool because it gives the model precise validation feedback it can repair.

Persistence

Do not add a cross-candidate checkpoint or “retry on next poll” state. Existing Notion request retries and per-idea idempotency are sufficient. The rare partial-write case is an operational exception, not justification for a new batch persistence subsystem.
